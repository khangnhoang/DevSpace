# Learning experience

Read this for lessons (`learn`), quizzes and exercises, the editor and run feedback of a code playground (including `try_it`, whose page composition follows [client-marketing.md](client-marketing.md)), notes and comments in a lesson, progress, certificates and the learner `profile`.

Direction: medium-to-high latitude. Focused, motivating, low friction. Spend expressiveness on interaction, immediate feedback, visible progress and completion. Personality must support focus, repeated use, keyboard use and mobile. A signature element comes from learning behavior (recall, progression, correction, completion), not decoration.

Prioritize a clear next action; obvious correct and incorrect feedback; visible progress; keyboard and mobile use; motion that clarifies reveal, progress or completion. The lesson content area (`LessonContent`, video, MDX) keeps its reading width and is not crowded by controls. Confetti on completion is fine if it never hides feedback or the next action and respects reduced motion.

The learner should always know: what am I doing, what happens next, was I correct, what should I learn from the result? Do not design UI that implies a saved quiz score unless the schema and the server action that store it exist.

Avoid clutter around the learning task, equal visual weight for too many actions, tiny answer controls, hidden feedback, motion that delays practice, and layouts that break on mobile. Paid lesson content is only shown after the enrollment check; do not render locked content as a teaser from data the user should not have.
