## QE-F1: Enforce test-data ownership, safe cleanup and recovery

- Status: Planned in Owner-approved QE-U1 r2; implementation authorized, not started; transferred from BL-F6 on 2026-10-30.
- Direction: implement the shared safety contract from [PR #39 testing policy](../../../.claude/skills/test-quality-strategy/SKILL.md) in existing test helpers and migrate affected tests to them. Replace broad cleanup such as deleting every payment except seed ID 1 or every coupon except LOCAL10 (`__tests__/e2e/service-role.ts:101`) and actor-wide/shared-marker cleanup where it can affect another run. Track owned IDs or run-scoped resources, preserve unrelated rows, protect failed preflight/setup, verify cleanup outcomes and define interrupted-run recovery. U1 test review at `4dd1c78` also identifies `removeE2eFixtures`: its before/after hooks delete all `E2E%` or `e2e-%` rows and `e2e-*@devspace.test` accounts, so another run or manual QA can lose its fixtures; `workers: 1` does not provide cross-process exclusivity. Replace the shared markers and fixed fixture names/email with ownership-scoped tracking, separate interrupted-run recovery from routine cleanup, and remove the first-page-only Auth scan (`perPage: 200`) when moving to owned user IDs. Add a test proving one run cannot remove another run's fixtures. The narrow U1 corrections make Auth read/delete errors fail loudly and verify user removal; they do not provide stack isolation or solve these ownership gaps. Add meaningful tests proving unrelated data survives, setup/test failure leaves no owned residue, and a second run is independent. Check the intended local target and exclusive use before writes/reset; loopback checks and one worker are insufficient across processes. Reuse [BL-F3](../../backlog/future-features.md) for the separately deferred dev/test-stack split if required; do not duplicate it, open extra stacks without approval or treat its deferred status as permission to reset shared data. Keep stable seed data minimal and service role restricted to setup/read-back/cleanup, never the request under test. No product or hosted-data change; shared helper changes and their callers ship together.

## QE-F2: Automate representative failure paths and concurrency invariants

- Status: Recorded; deferred until QE-F1 safe-fixture support is delivered and its own initiative is approved; transferred from BL-F7 on 2026-10-30.
- Direction: select concrete regression-worthy cases during discovery, using existing Vitest, real local database and Playwright/API helpers rather than adding a new test framework. Extend the E2E fixture to permit only explicitly expected request/status failures per test, with assertions for recovery and unchanged/persisted data; unexpected 5xx responses and external/hosted network access must still fail. Distinguish sequential retries, stale tabs and genuinely competing requests: the payment H2/K6 rows do not prove concurrent integrity. For relevant counters, reservations or state transitions, use independent requests/connections, identify the shared resource and assert the final invariant; use controlled synchronization when needed rather than claiming `Promise.all` guarantees a race. Keep normal user-flow wiring in browser E2E and endpoint/DB guarantees in integration tests where sufficient. Do not mock authorization or the database guarantee being tested. Use the existing known-bug contract for approved unresolved P5/P6/P25 cases; this entry does not authorize their product fixes. Keep real mail delivery/provider quality separate from application-side success/failure handling. Coordinate with BL-F2 and app-foundation coverage instead of duplicating those UI scenarios; no rewrite of the entire suite or blanket load/visual testing.
